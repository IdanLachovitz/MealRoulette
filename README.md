# מה מבשלים השבוע

אפליקציית ווב (PWA) לתכנון בישולים שבועי עם רולטת בחירה. עברית, RTL מלא, ניתנת
להתקנה במסך הבית בנייד.

נבנתה לפי `MealRouletteFiles/meal-planner-spec-he-v1.1.md`.

---

## איך זה בנוי

הכלל המרכזי: **המכשיר כותב אצלו קודם, ורק אחר כך מדבר עם השרת.**

```
   מסך  ──כתיבה──▶  IndexedDB (Dexie)  ──▶  תור כתיבות (outbox)
    ▲                     │                        │
    └──── useLiveQuery ───┘                        │  ברקע, כשיש רשת
                                                   ▼
                                          Supabase (Postgres + RLS)
                                                   │
                                                   ▼
                                            המכשיר השני
```

- **מנוע ההגרלה והתכנון רץ במכשיר**, לא בשרת (`src/engine/`). הוא פונקציה טהורה
  שמקבלת מאגר, היסטוריה, פרמטרים ו־seed ומחזירה תוצאה. עם seed קבוע התוצאה זהה
  בכל הרצה — ולכן כל חוקי הצינון וההרפיה מכוסים ביוניט טסטים בלי לפתוח דפדפן.
- **הגלגל הוא רק אנימציה** שמציגה החלטה שכבר התקבלה, ולכן הוא לא במסלול בדיקה.
- **התנגשויות**: Last Write Wins לפי `updated_at`, חוץ מסשן נעול — נעילה מנצחת גם
  כתיבה מאוחרת יותר.
- **מחיקות** הן רכות (`deleted_at`), כדי שהמכשיר השני ילמד על המחיקה במקום להחיות
  את השורה.

### מבנה

| תיקייה | מה יש בה |
|---|---|
| `src/engine/` | לוגיקה טהורה: תכנון, הגרלה, חישוב כמויות, תאריכים. כאן הטסטים |
| `src/db/` | סכמת Dexie, תור הכתיבות, ייבוא מאגר ההתחלה |
| `src/sync/` | לקוח Supabase, לולאת push/pull, הצטרפות למשק בית |
| `src/services/` | הפיכת תוכנית לשורות בבסיס הנתונים |
| `src/screens/` | המסכים |
| `supabase/schema.sql` | סכמת השרת + מדיניות RLS |

## הדלקת הסנכרון

### 1. פרויקט Supabase

1. נכנסים ל־[supabase.com](https://supabase.com) ופותחים פרויקט חדש (התוכנית החינמית מספיקה).
2. **SQL Editor** ← מדביקים את כל `supabase/schema.sql` ← Run. הקובץ ניתן להרצה חוזרת בלי נזק.
3. **Project Settings ← API** ← מעתיקים את `Project URL` ואת `anon public`.

### 2. מקומית

יוצרים `.env` (הועתק מ־`.env.example`):

```
VITE_SUPABASE_URL=https://xxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGci...
```

מריצים מחדש `npm run dev`. במסך ההגדרות יופיע כעת חלק "סנכרון".

> ה־anon key נועד להישלח ללקוח. מה שמגן על הנתונים זה ה־RLS שבסכמה, לא המפתח.

### 3. חיבור שניכם לאותו מאגר

1. שניכם נכנסים להגדרות ← סנכרון ← מזינים מייל ← מתחברים דרך הקישור שנשלח.
2. **אחד מכם** לוחץ "פרסמי את המטבח הזה לשרת".
3. הוא מוסר לשני את **קוד ההצטרפות** בן 6 התווים שמופיע בתחתית אותו כרטיס.
4. השני מזין את הקוד ולוחץ "הצטרפי".

מרגע זה כל שינוי אצל אחד מופיע אצל השני תוך שניות.

> בהצטרפות המכשיר עובר למאגר המשותף. המנות שהיו בו קודם נשארות תחת המטבח הישן —
> אם צריך אותן, מייצאים JSON לפני ההצטרפות.

## פרסום ל־GitHub Pages והתקנה בטלפון

### פעם אחת

```bash
git init && git add -A && git commit -m "Meal roulette v1.1"
```

יוצרים repo ריק ב־GitHub, ואז:

```bash
git remote add origin https://github.com/<user>/<repo>.git && git branch -M main && git push -u origin main
```

ב־GitHub:

1. **Settings ← Pages ← Source: GitHub Actions**.
2. **Settings ← Secrets and variables ← Actions ← Variables ← New variable** — מוסיפים
   `VITE_SUPABASE_URL` ו־`VITE_SUPABASE_ANON_KEY` (משתנים, לא secrets).

ה־workflow שב־`.github/workflows/deploy.yml` בונה, מריץ טסטים ומפרסם בכל `push` ל־main.

### התקנה במסך הבית

הכתובת תהיה `https://<user>.github.io/<repo>/`.

- **אנדרואיד (Chrome)**: תפריט ⋮ ← "התקן אפליקציה" / "הוסף למסך הבית".
- **אייפון (Safari)**: כפתור השיתוף ← "הוסף למסך הבית". חובה Safari — בכרום באייפון זה לא יעבוד.

אחרי ההתקנה האפליקציה נפתחת במסך מלא ועובדת גם בלי רשת.

## הערות על מימוש האפיון

- **הרולטה מגרילה מכל המאגר הזמין** גם כשהגלגל מציג תת־קבוצה. מעל 8 פריטים התוויות
  מוסתרות, ומעל 12 (בגלגל המנות) מוצגת תת־קבוצה — ההגרלה עצמה תמיד מכל המאגר.
- **FR-3.9** (טבעת הירק הצרה) מומש: הטבעת הפנימית מוגבלת ל־4 פרוסות ומציגה תת־קבוצה
  מתחלפת כשיש יותר.
- **"שאריות" מול "לא מבשלים"**: יום שאריות הוא כרטיס מקווקו עם אייקון ♻️ ועם שם המקור
  ("שאריות מהלזניה"). "לא מבשלים" הוא שורה **בלי כרטיס בכלל**. ההבדל שורד גם בשחור־לבן
  וגם במצב כהה.
- **אשף התכנון מגריל מנות מלאות בלבד**, כפי שסעיף 7 מנוסח. הרכבות נוצרות מהרולטה
  ומשובצות ליום.
- **סתירה באפיון שנפתרה**: FR-5.5 מגדיר "אין חזרה על מנה באותו שבוע" כחוק קשיח, אבל
  תנאי הקבלה של FR-5.3 מצפה שמנה תחזור כשהמאגר קטן מדי. המימוש מכבד את החוק הקשיח כל
  עוד קיימת חלופה כלשהי, ושובר אותו רק כדי לא להשאיר סשן ריק — עם הודעה נפרדת.
- **שאלות פתוחות מסעיף 12** נסגרו לצורך המימוש כך: סימון "בושל" הוא ידני; שיבוץ אחד
  ליום; רשימת מדפים סגורה; תקרת `covers_days` היא 4; מספר הסועדים הוא ברמת משק הבית
  (עם `fixed_servings` לדריסה ברמת מנה).
